# 2026-10-13 工作日志

## 策略查询维度接口拆分 + 缓存（dates/periods/directs 独立接口）

### 需求
将 `/api/strategy/reports` 中的维度下拉（dates/periods/directs）抽离为独立接口，避免每次列表查询都去 `strategy_reports`（约 264 万行）做 `DISTINCT` 全表统计。

### 落地内容
1. **新增 3 个独立接口**（均登录即可，`requireUser`）：
   - `GET /api/strategy/dates` → 按 period 分组 `{ day: [...], week: [...] }`（动态 key）。
   - `GET /api/strategy/periods` → `{ periods: [...] }`。
   - `GET /api/strategy/directs` → `{ directs: [...] }`。
2. **缓存**（`strategy-cache.ts`）：
   - 固定 key：`strategy:dates` / `strategy:periods` / `strategy:directs`，TTL **7200s（2 小时）**（`strategyCache.metaTtl` 由 600 改为 7200）。
   - 列表缓存仍走版本号 `strategy:list:{version}:{md5}`（listTtl=120s）。
   - 失效函数 `invalidateStrategyCache()`：`INCR strategy:version` + `DEL` 三个 meta key（取代原 `bumpStrategyVersion`）。
3. **`reports.get.ts`**：移除 directs/periods/dates，仅返回列表 `{records,total,page,pageSize}`。
4. **`report.post.ts`**：写库成功后调用 `invalidateStrategyCache()`。
5. **前端 `index.vue`**：`dates` ref 改为 `datesByPeriod`（分组），`currentDates` computed 按 `filters.period` 取值；新增 `fetchMeta()` 并行请求三个独立接口；周期切换 `@change="onPeriodChange"` 重置日期为最新。
6. **`strategy-reports.ts`**：`fetchMetaRaw` 拆为 `fetchDatesGroupedRaw` / `fetchPeriodsRaw` / `fetchDirectsRaw`（dates 用 `SELECT DISTINCT period, resolve_date::text ... ORDER BY period, d`）。
7. 文档 `docs/api.md` 新增 2.2/2.3/2.4 接口说明 + 更新缓存说明与端点索引。

### 验证（dev 冒烟，真实登录 token）
- dates 返回 `{"day":[...666 个日期]}`（当前库 period 仅 day，未来有 week 自动分组）。
- periods `{"periods":["day"]}`；directs `{"directs":["0","1"]}`。
- reports keys 仅 `records,total,page,pageSize`（无维度残留）。
- `strategy:dates` TTL ≈ 7200s；上报一次后该 key `exists=0`（已清掉）。

### 备注
- 当前数据库 `period` 仅有 `day`（666 个不同日期）；dates 接口按 period 动态分组，未来接入 `week` 数据无需改动即返回 `{week, day}`。
