## Bug 修复：登录后仍停留登录页（Secure cookie 与 HTTP 冲突）

### 根因
`server/utils/session.ts` 的 `setAuthCookie` 用 `secure: !import.meta.dev`，生产构建下 cookie 带 `Secure` 属性。
但站点是纯 HTTP 部署（80 端口，无 HTTPS），浏览器拒绝存储 Secure cookie → 登录/改密后无法建立会话 → auth 中间件 fetchMe 401 → 被踢回 `/login`。
线上验证：登录 Set-Cookie 头含 `Secure; SameSite=Lax`（curl 实测确认）。

### 修复
- `nuxt.config.ts` runtimeConfig 新增 `cookieSecure: process.env.NODE_ENV === 'production'`（可被 `NUXT_COOKIE_SECURE` 覆盖）
- `server/utils/config.ts` 新增 `cookieSecure` 字段 + `parseBool` 解析
- `server/utils/session.ts` `setAuthCookie` 改用 `getConfig().cookieSecure`
- `.env.production` / `.env.example` 新增 `NUXT_COOKIE_SECURE=false`（HTTP 部署）
- 重新构建部署，验证 Set-Cookie 不再带 Secure，登录态链路（/api/auth/me、/api/strategy/reports）均 200

### 遗留提醒
- 上 HTTPS 后需把 `NUXT_COOKIE_SECURE` 改为 `true`

## 策略查看页查询性能优化（Redis 缓存 + 索引）

### 背景
`GET /api/strategy/reports` 返回过慢。实测 `strategy_reports` 表约 264 万行，原实现每次请求都做：`SELECT *`（含大 TEXT JSON 列）+ `COUNT(*)` 全表 + 3 个 `DISTINCT` 全表扫描（directs/periods/dates），且日期筛选用 `(tactic_resolve_time AT TIME ZONE 'Asia/Shanghai')::date` 表达式无法走索引。

### 落地内容
1. **迁移 `005_strategy_query_indexes.sql`**：新增 `resolve_date DATE` 预计算列（写库时由 JS 计算 Asia/Shanghai 日期，与 SQL 语义一致，迁移回填 264 万行）+ 索引 `resolve_date`、`direct`、`period`、`analyze_score DESC`、组合 `(period, resolve_date)`、pg_trgm GIN（stock_number/stock_name）。
2. **`server/utils/cache.ts`**：通用 cache-aside（`cacheGetOrSet`）——空结果缓存防穿透、`SET NX` 单飞锁防击穿、Lua compare-and-delete 释放锁。
3. **`server/utils/strategy-cache.ts`**：generation-based 失效——写库 `INCR strategy:version`，缓存键 `strategy:list:{version}:{md5}`、`strategy:meta:{version}`；`cachedListReports`（缓存原始行，读取时按角色裁剪）、`cachedStrategyMeta`。
4. **`strategy-reports.ts`**：`SELECT *` → 窄列（剔除 hash/ud_str/must_eles/report_ts/时间戳）；日期筛选改用 `resolve_date = ANY($n::date[])`；拆分 `queryReportRows`（原始查询）/`fetchMetaRaw`（元数据加载器）。
5. **接线**：`report.post.ts` 写库成功后 `bumpStrategyVersion()`；`reports.get.ts` 并行调用 `cachedListReports` + `cachedStrategyMeta`。
6. **配置**：runtimeConfig/config.ts/.env.example 新增 `strategyCache`（metaTtl=600/listTtl=120/lockTtl=10）。

### 验证
- 迁移成功，索引齐备，264 万行 resolve_date 回填 missing=0。
- `nuxt build` 编译通过；dev 冒烟：health ok、未登录 401、上报 200（23 列写入含 resolve_date 成功）、版本号 1→2、JS 与 SQL 的 resolve_date 一致。
- 注意：dev 服务在 Windows 上仅监听 `localhost`(::1)，`127.0.0.1` 连不上。
