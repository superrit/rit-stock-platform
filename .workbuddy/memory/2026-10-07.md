# 2026-10-07 工作日志

## 生产环境部署（rit-stock-platform → 腾讯云 134.175.143.160）

### 目标
将 Nuxt 4 项目部署到生产服务器，监听 80 端口，与已有 GitLab CE（5003 端口）共存。

### 服务器环境探测结果
- Ubuntu 26.04 x86_64，2 核 3.6GB（GitLab 占用约 2.8GB，可用内存紧张）
- 初始无 Node.js / PostgreSQL / Redis；80 端口空闲；GitLab 经 gitlab-runsvdir 运行在 5003
- `ubuntu` 用户免密 sudo 可用

### 落地内容
1. **新增部署脚本 `scripts/deploy.mjs`**（封装为 `npm run deploy` / `npm run deploy:skip-build`）：
   - 基于 `ssh2`（新增 devDependency，SSH_PASSWORD 密码认证）
   - 基于 `tar`（node-tar，新增 devDependency）本地纯 JS 打包，不依赖系统 tar/curl 二进制
   - 流程：构建 → 注入 Linux sharp → 打包 → SFTP 上传 → 环境初始化（幂等）→ 写 systemd → 重启 → 健康检查
   - 支持 `--skip-build` / `--skip-provision` / `--dry-run`
2. **跨平台 sharp 加固**：Windows 构建默认只打包 `@img/sharp-win32-x64`；脚本自动下载 `@img/sharp-linux-x64` + `@img/sharp-libvips-linux-x64` 注入 `.output`（strip:1 解压，缓存到 `node_modules/.cache/deploy-sharp`）。注：应用未使用图片优化，ipx 惰性 `import("sharp")`，此步为防御性可选。
   - 曾踩坑：yarn 无法在 win32 安装 `@img/sharp-libvips-linux-x64`（os/cpu 限制）；改名 `renameSync` 跨盘（C:→D:）报 EXDEV，改用 `strip:1` 直接解压。
3. **服务器初始化**（幂等，脚本自动完成）：
   - Node.js 22.22.2（官方 tarball → `/opt/nodejs`，symlink 到 `/usr/local/bin`）
   - PostgreSQL 18 + Redis 8（apt）
   - 建库 `rit_stock_platform` + schema + 迁移 + 种子超管 `13800000000/000000`
4. **systemd 服务** `/etc/systemd/system/rit-stock.service`：
   - `User=ubuntu`，`AmbientCapabilities=CAP_NET_BIND_SERVICE`（非 root 绑 80）
   - `EnvironmentFile=/opt/rit-stock-platform/rit.env`（仅 NUXT_*，chmod 600）
   - `ExecStart=/opt/nodejs/bin/node .output/server/index.mjs`，`Restart=always`，开机自启
   - 监听 `NITRO_PORT=80 NITRO_HOST=0.0.0.0`
