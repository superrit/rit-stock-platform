## 策略查看页：清空全部策略功能（仅超级管理员 + 密码确认）

### 需求
管理员在策略查看页可清空全部策略；仅管理员可用，接口防越权；点击后需输入本人登录密码确认，通过后才清空。

### 落地内容
1. **后端 `server/api/strategy/reports.delete.ts`（新增）** `DELETE /api/strategy/reports`：
   - `requireAdmin` 强制 `super_admin`（非管理员 403）。
   - `readBody({password})`，空密码 400。
   - 查当前管理员 `password_hash/salt`，`verifyPassword` 校验（错误 401「密码错误，无法清空」）。
   - 通过后 `TRUNCATE TABLE strategy_reports`（秒级，避免长时间锁表影响上报）。
   - `invalidateStrategyCache()` 失效缓存（列表版本号 +1、dates/periods/directs DEL）。
2. **前端 `app/pages/index.vue`**：
   - `isAdmin = computed(() => user.value?.role === 'super_admin')`。
   - 筛选栏新增「清空全部」danger 按钮（`v-if="isAdmin"`）。
   - `onClearAll`：`ElMessageBox.prompt`（type=warning、inputType=password、非空校验）→ `$fetch DELETE` → 成功后 `fetchMeta + applyDefaultFilters + fetchData` 刷新。
3. **文档 `docs/api.md`**：新增 2.5 接口说明 + 端点索引加 DELETE 行。

### 验证（dev 冒烟，无损 RENAME 换表法）
- 普通用户 → 403；未登录 → 401；超管错误密码 → 401；超管正确密码 → 200 且 `strategy_reports` 行数 0。
- 真实表（264 万行 / 3.8GB）用 `ALTER TABLE ... RENAME` 换表法临时隔离测试，测试后恢复，未破坏数据。
- `nuxt build` 编译通过。

## 去掉「结果订单数」展示 + 接口防刷（IP 限流）

### 需求
1. 详情面板去掉「结果订单数」展示。
2. 接口防刷：每个 IP 每分钟最多访问 600 次。

### 落地内容
1. **`app/components/StrategyDetail.vue`**：删除「结果订单数」`detail-item`（对应 `row.total`），保留 K线索引/BSP/JXP/PL。
2. **接口限流 `server/middleware/rate-limit.ts`（新增，全局限流中间件）**：
   - 仅对 `/api/*` 生效，按 `getRequestIP(event, {xForwardedFor:true})` 取 IP。
   - Redis `INCR` + 首次 `EXPIRE 60s`，用 Lua 保证原子（key `ratelimit:{ip}`，滚动 60s 窗口）。
   - 超过 600 抛 429「请求过于频繁，请稍后再试」；Redis 异常 fail-open（不阻断请求）。
3. **配置**：runtimeConfig 新增 `rateLimitPerMinute`（默认 600，0 表示禁用）；`config.ts`/`nuxt.config.ts`/`.env.example` 同步。
4. **文档**：`docs/api.md` 通用说明加限流条款。

### 验证（dev 冒烟）
- 限流：发 601 次 `/api/health`（含 waitHealth 预占 1 次），前 600 次 200、第 601 次起 429，响应体正确。
- `nuxt build` 编译通过。
